军训前我就完成了基本素养的了解和个人网站的制作。但是因为之前完全是技术小白，第一次接触到 GitHub 这种这么大型的工具，所以一开始用得很不顺利（直到现在我也不能说我把它玩明白了）。我一边用 AI 慢慢摸索，一边在 B 站上搜索相关的使用教程才迷迷糊糊地能用顺。可以说我是在用上 GitHub 和其内置插件的 Agent 之后，才真切地感受到稍微前沿一点的世界，以及这次工业革命对于生产力的解放之大。在这里是很感谢这次集协一面的，就算没进，我也在这过程中学到了很多宝贵的东西，包括但不限于对于命令、本专业知识的了解，对于工具的使用和优化路径的了解，以及对于科技世界的初探。

军训后到国庆才有时间继续这个项目的制作，但是这时候对于一些 GitHub 的操作使用的程序已经又只剩模糊的印象，而且我一开始建了多个仓库，一时间找不到最终到底要用哪个。所以贪吃蛇程序一开始有好几个提交是混乱的，有 12 个我甚至当时没招了（而且网也很不好，当时不用 VPN 会时不时断联，实际上现在用了也会，不过好一点）直接从云端拉取的，导致后续推送时没法同步，出现 conflict。因为对各种名词不熟练，我只能不停拍照给元宝，它再根据情况给我命令，我在终端敲了大半天的命令。后来发现它没有明白我的规划，而且也解决不了网络的问题，甚至把我的网页和个人网站部分都删了，十分混乱，但是我又不想重开一个仓库丢掉前面提交的记录。所以我及时止损，突然想起来我可以用 VS Code 里面内置 Agent 插件 DeepSeek，让它把前面元宝的 100 多次修改都撤销，回到军训开始前的状态，重新分步骤提交贪吃蛇的代码，修好了分支和个人网站的部署。后面就越来越熟练，一路做了下来。Agent 的办事效率真是挺高的，只要命令写得清晰，效果基本都可以达到预期。整体项目对我来说除了电路知识的学习，就是 GitHub 的环境使用有些挑战。这也是我的第一个相关项目，我尽力打磨它了，但是肯定还是会有许多瑕疵，不过我在过程中学到了很多！！接下来是正文！欢迎对后面的内容进行交流探讨！！ ヾ(✿ﾟ▽ﾟ)ノ

### 1.2 相关解释

#### 分支合并

- **分支**：分支即为副本，另存了之后可以像游戏支线一样自己发展改动，与主线无关了，但是可以把副本里做得好的部分合并到主线上来，就像一个允许试错的草稿。`main` 分支是主分支（`main` 也是一个分支！），其他分支是 feature 分支，可以合并到 `main` 分支上。
- **合并**：把 feature 分支上的合适的改动合并到 `main` 分支上，变成 `main` 分支上的改动。

#### 基本命令行

##### GitHub 工作流程（我的理解）

```
工作区（VS Code 编写代码）
    ↓ git add
暂存区（准备提交）
    ↓ git commit
本地仓库（保存历史版本）
    ↓ git push
远程仓库（GitHub 网站）
```

改文件 → `git add`（进暂存）→ `git commit`（进本地历史）→ `git push`（上 GitHub）

##### 终端命令

| `pwd` ：查看当前所在目录，即当前工作目录
| `ls`（或 `dir`） ：查看当前目录下的文件和目录
| `cd`（或 `chdir`） ：切换目录，进 / 出某个目录
| `mkdir` ：创建目录
| `rm` （或 `del`） ：删除文件或目录
| `cp` ：复制文件或目录
| `mv` ：移动文件或目录

##### Git 命令

**日常提交：**

| `git status` ：查看当前工作区状态，不确定文件状态的时候多看看这个！这样可以做出更正确的决策！血泪经验！！
| `git add <文件>` ：将文件添加到暂存区，准备提交
| `git commit -m "信息"` ：提交暂存区文件到本地历史，附带提交信息
| `git push` ：将本地提交上传到 GitHub 远程仓库
| `git pull` ：从 GitHub 远程仓库拉取最新代码到本地
| `git log` ：查看本地历史提交记录

**撤销 & 回退：**

| `git restore <文件>` ：丢弃某个文件未提交的修改
| `git restore --staged <文件>` ：取消暂存但保留修改
| `git reset <文件>` ：将文件从暂存区移除，回到工作区
| `git reset --soft HEAD~1` ：撤销上次 commit，改动保留在工作区
| `git reset --hard HEAD~1` ：撤销上次 commit，改动也丢弃
| `git reflog` ：找回好像丢了的提交历史

**分支操作：**

| `git branch` ：查看所有分支
| `git switch -c <分支名>` ：新建并切换到该分支
| `git switch main` ：切换回主分支
| `git merge <分支名>` ：将该分支合并到当前分支

### 3.2 main 优化

#### 优化目标

1. 手动模式增加难度选择，不同难度下蛇速、分数倍率不同
2. 渐进加速：每吃 5 个食物蛇自动加快
3. 障碍物机制：蛇短时生成障碍物，碰撞扣分+缩短
4. AI 模式与手动模式兼容，AI 下自动锁定难度
5. 三栏布局适配桌面端，加入虚拟方向键适配安卓手机
6. 删除阶段一 HTML，只保留阶段二

#### 具体改动

| 功能 | 说明 |
|------|------|
| 难度选择 | 简单 / 普通 / 困难 / 地狱，4 档速度 + 分数倍率 |
| 渐进加速 | 每吃 5 个食物，速度加快（最低 30ms），难度越高加速越明显 |
| 障碍物 | 蛇身 < 8 节时生成 3 个障碍物，碰到后蛇缩 2 节 + 扣 10 分 |
| 三栏布局 | 左栏（提示/规则） + 中栏（画布） + 右栏（分数/控制面板），无需滚屏 |
| 移动端适配 | 画布下方 4 方向虚拟按键（D-Pad），安卓手机可直接触屏操作 |
| AI 兼容 | AI 模式下难度按钮自动禁用，不可切换 |
