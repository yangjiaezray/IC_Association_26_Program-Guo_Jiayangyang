## 项目制作过程

这是本人的第一个技术项目。期间最大的挑战是 GitHub 工作流的使用：多仓库管理混乱、网络不稳定导致 push/pull 频繁 conflict、不同 AI 工具（元宝 vs DeepSeek-V4-Pro）的效果差异。在多次终端操作后，改用 VS Code 内置 Agent 插件 DeepSeek 将元宝的 100 多次无效修改回退到干净状态，重新分步提交，修复了分支和个人网站部署。后续熟练后效率明显提高。

项目中 AI 辅助编程的核心经验：AI 在纯代码逻辑（算法、数据结构、功能实现）方面表现稳定；在涉及浏览器底层行为（Canvas 图片渲染、iOS 兼容性）时容易出错。亲自运行代码是唯一的查证标准。

## 三、贪吃蛇代码

### 3.1 概述

基于 Canvas 的单机贪吃蛇游戏。支持手动操作与 AI 自动对战两种模式，包含难度选择、皮肤切换、背景纹理、战绩记录等扩展功能。

### 3.2 查证：AI 给出但经运行验证为错误的信息

以下由 AI (DeepSeek-V4-Pro) 在对话中提出，经亲自运行确认不可行：

| 编号 | AI 方案 | 实际结果 | 处理 |
|------|--------|---------|------|
| ① | iOS 兼容性适配 | 修改 20 分钟后持续报错 | `git checkout` 回滚 |
| ② | JPG 图片通过 `drawImage()` 渲染为 Canvas 背景 | 游戏画面崩溃 | 回滚 |
| ③ | JPG 图片裁切为圆形蛇头贴图 | 渲染异常，蛇头花屏 | 回滚 |
| ④ | 图片上加 55% 暗色蒙层使蛇身突出 | 渲染问题依旧，体验不佳 | 回滚，放弃图片方案 |
| ⑤ | Canvas 纯代码手绘人物作为动态背景 | 能运行，但画面简陋 | 用户判断不合格 |
| ⑥ | `git cherry-pick` 同步 README 到 main | cherry-pick 卡死，阻塞分支切换 | `cherry-pick --abort` 清理 |

**总结**：AI 在难度系统、速度算法、localStorage、皮肤配色、布局重构等纯代码逻辑上表现稳定；在图片加载、Canvas 渲染、iOS 兼容等涉及浏览器底层行为时易出错。

### 3.5 AI 核心算法机制分析（防纯粘贴说明）

- **BFS 寻路**：广度优先搜索，逐层扩散寻找最短路径，被阻挡时停止该方向扩散，避免探索死路
- **追尾保命**：蛇身围住食物形成环路时自动追尾，利用蛇尾持续移动打破死胡同。实测发现仍可能陷入环形死锁（AI 首局停在 199 分无法吃到下一食物）
- **饥饿模式**：棋盘 400 格，约 300 步可遍历大部分区域。超过 350 步未吃到食物时，判定为环形死锁，启动宽松检查强制寻路，风险增大但可打破僵局

#### 3.6.4 启示

1. AI 适合做"翻译官"：把模糊需求翻译为具体实现（皮肤配色、背景模式等）
2. AI 不适合做"魔术师"：本地 JPG 在 Canvas 实时渲染 → 翻车率高
3. 最佳工作模式：人提方向 → AI 出方案 → 人拍板 → AI 施工 → 人测试验证
4. Git 版本管理是 AI 协作的基础：每次改坏可直接 `git reset --hard`，敢于试错
5. 提示词不需要精确：说人话即可，AI 自行补全细节
6. 最关键技能是验证结果而非写提示词：亲自跑一遍代码比任何高级提示词都重要
7. 让 AI 验证 AI：一句提示词让 AI 写 150 局自动化测试，3 秒出结果，数据驱动优化

## 四、电路模块（进阶任务二：验证戴维南定理）

> 进阶任务一和三尚未完成，后续补充。

### 4.1 概述

使用 PySpice + Ngspice 47 对含 VCCS（电压控制电流源）的线性有源二端网络进行直流仿真分析。验证其对外特性可等效为戴维南等效电路（5V 电压源串联 5Ω 电阻），并通过全范围扫描负载电阻验证最大功率传输定理。

### 4.2 电路拓扑

```
        Us = 10V
         ┌───┐
    ┌────┤ V │──────┐
    │    └───┘      │
    │     n1        │
    ├───/\/\/───┐   │
    │    R1=5Ω  │   │
    │           └───┼─── a ─── RL ─── GND
    │    ┌─────┐    │
    │    │VCCS ├────┤  GM = 0.1 S
    │    └──┬──┘    │  I = GM × V(R1)，方向 a → GND
    ├───/\/\/───────┘
             R2=10Ω
              │
             GND
```

- 电压源 Us = 10V
- R1 = 5Ω（串联），R2 = 10Ω（并联）
- VCCS：跨导 GM = 0.1 S，电流 I = 0.1 × V(R1)

### 4.3 手算推导

#### ① 开路电压 Uoc（RL → ∞）

KCL @ a：

$$\frac{V(a) - 10}{5} + \frac{V(a)}{10} + 0.1(10 - V(a)) = 0$$

$$\boxed{U_{oc} = 5.000\ \text{V}}$$

#### ② 短路电流 Isc（RL → 0）

V(a) = 0，R2 被短路：

$$I_{R1} = \frac{10}{5} = 2\ \text{A}, \quad I_{VCCS} = 0.1 \times 10 = 1\ \text{A}$$

$$\boxed{I_{sc} = 2 - 1 = 1.000\ \text{A}}$$

#### ③ 等效电阻 Req

**方法 A** · 开路短路法：

$$R_{eq} = \frac{U_{oc}}{I_{sc}} = \frac{5.000}{1.000} = \boxed{5.000\ \Omega}$$

**方法 B** · 加压求流法（含受控源的正统做法，独立源置零，端口加测试电压）：

$$I = \frac{U}{10} + \frac{U}{5} - 0.1U = 0.2U \quad\Rightarrow\quad R_{eq} = \frac{U}{I} = \boxed{5.000\ \Omega}$$

**方法 C** · 串并联法（错误示范）：

$$R_1 \parallel R_2 = \frac{5 \times 10}{5 + 10} = 3.33\ \Omega \quad\leftarrow \text{受控源存在时失效}$$

### 4.7 核心结论

**原网络（含 VCCS 受控源）与戴维南等效电路（5V 串联 5Ω），在 RL ∈ [0.1Ω, 10kΩ] 全范围内输出电压完全一致，最大相对误差仅 2.59×10⁻¹⁶（双精度浮点舍入误差）。**

- 等效电路的 V-I 特性曲线与原网络完全重合 → 从端口看去，外部无法区分两者 → 戴维南定理成立
- RL = Req = 5Ω 时 Pmax = 1.25W（效率 50%），验证最大功率传输定理
- 含受控源时串并联法求 Req 失效（得 3.33Ω），必须用开路短路法或加压求流法
